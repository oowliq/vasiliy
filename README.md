# Василий

Бот для дружеского сервера в [Fluxer](https://fluxer.app) — открытой альтернативе Discord.
Считает статистику голосовых каналов, подводит итоги недели, выдаёт ачивки, хранит цитаты,
напоминает, поздравляет с днём рождения и собирает народ на катку.

- Node.js ≥ 22.13 (используется встроенный `node:sqlite`), TypeScript, pnpm
- SDK: [`@fluxerjs/core`](https://fluxer.js.org)
- Данные — один файл SQLite (`data/stats.db`)
- Время везде по МСК

## Возможности

### Статистика

| Команда | Что делает |
| --- | --- |
| `!stats [@участник]` | Статистика за неделю и за всё время, серия дней в голосе, лучший напарник |
| `!top` | Топ текущей недели на данный момент |
| `!compare @участник` (`!vs`) | Сравнение по всем показателям со счётом по категориям |
| `!achievements [@участник]` (`!ach`) | Полученные и оставшиеся ачивки |

Бот считает: время в голосе, время и число попаданий в AFK-канал, серверный мьют и самомьют
(отдельно), стримы, камеру, ночное время (00:00–06:00), сообщения, совместное время пар.

Каждый **понедельник в 09:00 МСК** в канал объявлений приходят итоги недели с номинациями
(MVP, Король AFK, Молчун, Полуночник, Стример, Звезда камеры, Болтун, Дуэт недели) и топами.
Победитель конкурса — участник с наибольшим временем в голосе (без AFK) за предыдущую
календарную неделю: понедельник 00:00 — следующий понедельник 00:00 МСК.

Администратор задаёт две разные роли: `default_role` и `weekly_role`. Перед выдачей бот
снимает `weekly_role` со всех её обладателей и возвращает им `default_role`.
В конкурсе участвуют только люди с `default_role` (включая прежнего победителя после возврата).
Победитель получает `weekly_role` вместо `default_role`. Боты не участвуют.
Для выбора победителя нужны минимум два участника конкурса с ненулевым временем в голосе
за прошлую неделю. Если таких участников меньше двух, `weekly_role` не выдаётся, а прежним
обладателям возвращается `default_role`. При равном времени выигрывает участник с меньшим ID.
Остальные статистические топы и номинации по-прежнему охватывают весь сервер.

Роли назначаются независимо от наличия канала объявлений. При ошибках бот повторяет попытку,
сохраняя выбранного победителя; объявление отправляется после успешной смены ролей.
После простоя бот обрабатывает последнюю завершённую неделю. Планировщик проверяет срок
раз в минуту, поэтому отправка может произойти в течение минуты после 09:00.

Сам бот пишет и о сериях дней в голосе (3, 7, 14, 30… дней подряд, а также о прерванных),
о новых ачивках и днях рождения (в 10:00 МСК).

### Развлечения

| Команда | Что делает |
| --- | --- |
| `!coinflip` (`!flip`, `!монетка`) | Орёл или решка |
| `!roll [2d6 \| d20 \| 100]` | Кубики |
| `!choose пицца \| суши` | Выбрать вариант (также через «или» и запятые) |
| `!8ball вопрос` | Магический шар |
| `!poll Вопрос \| вар1 \| вар2` | Опрос с реакциями (без вариантов — да/нет) |

### Общение

| Команда | Что делает |
| --- | --- |
| `!quote` | Ответом на сообщение — сохранить в цитатник; без ответа — случайная цитата. `!quote @участник`, `!quote 5`, `!quote delete 5` |
| `!bday 15.03` | Указать день рождения; `!bday` — ближайшие, `!bday remove` — удалить |
| `!remind 1h30m текст` | Напоминание (`30m`, `2ч`, `3д`, `1w`); `!remind list`, `!remind cancel N` |
| `!lfg CS 5` | Сбор на игру: участники жмут ✅, когда состав собран — бот всех зовёт |
| `!help [команда]` | Список команд или подробности по одной |

Новых участников бот приветствует в системном канале сервера (или в канале объявлений).

### Для администраторов

| Команда | Что делает |
| --- | --- |
| `!channel [off]` | Сделать текущий канал каналом объявлений бота |
| `!default_role @роль \| off` | Роль участников конкурса |
| `!weekly_role @роль \| off` (`!mvprole`) | Роль победителя недели |
| `!welcome on \| off` | Включить/выключить приветствия |
| `!purge` | Удалить **все** сообщения и вложения на сервере (каналы остаются). Требует `!purge confirm` в течение минуты |

## Настройка бота в Fluxer

1. Создайте приложение и бота, скопируйте токен.
2. Пригласите бота на сервер с правами:
   - **Читать сообщения / Отправлять сообщения**
   - **Читать историю сообщений** и **Управлять сообщениями** — для `!purge`
   - **Добавлять реакции** — для опросов и сборов
   - **Управлять ролями** — роль бота должна стоять выше `default_role` и `weekly_role`
3. Администратор выполняет `!channel` в канале, куда боту писать объявления и победителя недели.
4. Администратор задаёт роли: `!default_role @роль` и `!weekly_role @роль`.
   Первая выдача — в ближайший понедельник в 09:00 МСК. `off` у любой из этих команд
   отключает конкурс и отменяет незавершённую выдачу, сохраняя уже выданные роли.
   Если настроенная роль удалена, используйте `off`, затем задайте новую роль. `!channel off` отключает только объявления.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
| --- | --- | --- | --- |
| `FLUXER_BOT_TOKEN` | да | — | Токен бота |
| `FLUXER_INSTANCE` | нет | официальный fluxer.app | Адрес своего инстанса, например `https://fluxer.example.com`. Адреса API и гейтвея берутся из `/.well-known/fluxer` |
| `BOT_PREFIX` | нет | `!` | Префикс команд |
| `STATS_DB_PATH` | нет | `data/stats.db` | Путь к базе SQLite |

Шаблон — в `.env.example`:

```bash
cp .env.example .env
```

## Деплой через GitHub Container Registry

Workflow [`.github/workflows/docker.yml`](.github/workflows/docker.yml) на каждый пуш:

1. ставит зависимости и гоняет тесты;
2. собирает Docker-образ под `linux/amd64` и `linux/arm64`;
3. публикует его в `ghcr.io/<владелец>/<репозиторий>`.

| Событие | Теги образа |
| --- | --- |
| Пуш в `main` | `latest`, `sha-abc1234` |
| Тег `v1.2.3` | `1.2.3`, `1.2`, `sha-abc1234` |
| Pull request | Только тесты и проверочная сборка, без публикации |

Токен для публикации — встроенный `GITHUB_TOKEN`, секреты заводить не нужно.

### Первый запуск

1. Создайте репозиторий на GitHub и запушьте код:

   ```bash
   git init && git add . && git commit -m "Initial commit"
   ```

   ```bash
   git branch -M main && git remote add origin git@github.com:OWNER/vasiliy.git && git push -u origin main
   ```

2. Дождитесь зелёного прогона во вкладке **Actions**. Образ появится в разделе **Packages** профиля.
3. Пакет по умолчанию приватный. Либо сделайте его публичным (**Package settings → Change visibility**),
   либо залогиньтесь на сервере токеном с правом `read:packages`:

   ```bash
   echo "$GHCR_TOKEN" | docker login ghcr.io -u OWNER --password-stdin
   ```

### На сервере

Нужны Docker и Docker Compose. Скопируйте на сервер [`compose.yaml`](compose.yaml), замените в нём
`OWNER` на свой логин (строчными буквами) и положите рядом `.env` с токеном.

```bash
docker compose up -d
```

База лежит в именованном томе `bot-data` и переживает обновления образа.

Обновиться до свежего `latest`:

```bash
docker compose pull && docker compose up -d
```

Логи:

```bash
docker compose logs -f bot
```

Бэкап базы:

```bash
docker compose cp bot:/app/data/stats.db ./stats-backup.db
```

> Чтобы сервер подтягивал новые образы сам, можно добавить в `compose.yaml` контейнер
> [Watchtower](https://containrrr.dev/watchtower/), который следит за `latest`.

### Сборка образа вручную

```bash
docker build -t vasiliy .
```

```bash
docker run -d --name vasiliy --env-file .env -v vasiliy-data:/app/data vasiliy
```

## Как устроен проект

```
src/
  index.ts          точка входа: клиент Fluxer, подключение к инстансу
  app.ts            сборка зависимостей, события гейтвея, планировщик
  db.ts             SQLite и миграции колонок
  settings.ts       настройки сервера (канал объявлений, роль MVP, …)
  time.ts           МСК, недели, длительности
  util.ts           упоминания, склонения, разбивка длинных сообщений
  commands/         команды: статистика, развлечения, общение, админка, purge
  stats/            трекер голоса, хранилище, недельный отчёт
  features/         ачивки, серии, цитаты, дни рождения, напоминания, LFG, приветствия
```

Неделя начинается в понедельник в 00:00 МСК. Каждую минуту бот сбрасывает в базу накопленное
время голосовых сессий, а при остановке (SIGTERM) сохраняет остаток и закрывает базу.
Сборы `!lfg` живут только в памяти и после перезапуска перестают обновляться.

При обновлении с прежнего расписания старые недельные суммы сохраняются в общей статистике.
Точно переразбить их по календарным неделям нельзя: исходных событий в БД нет.
Первая календарная неделя после обновления содержит только данные, собранные новым расписанием.
Ранее настроенная роль через `!mvprole` сохраняется как `weekly_role`; для конкурса нужно
дополнительно задать `default_role`.
